SECTION 1 — PROJECT OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Build a full-stack web application called the Invisible Work Analytics System (IWAS) — a data-driven productivity platform for software development teams that captures, classifies, and visualizes the full spectrum of developer effort, including work that traditional productivity metrics (commits, tickets, story points) completely miss.

The core insight this system operationalizes: developers spend significant time on invisible work — code reviews, debugging, mentoring teammates, knowledge sharing, handling production incidents, learning new technologies — that never appears in sprint dashboards or performance reviews. IWAS makes this work visible, measurable, and actionable.

PRIMARY USERS:
- Developers — log daily activities, view personal dashboards, track their own IWR and burnout risk
- Managers / Team Leads — view team-wide dashboards, compare effort distribution across developers, identify burnout risk early

CORE VALUE PROPOSITION:
Replace distorted productivity pictures with a fair, complete, data-driven view of actual developer contribution. Reduce burnout risk by surfacing effort patterns before they become crises.

MODULE 1 — AUTHENTICATION
- Developer and Manager roles with distinct access levels

MODULE 2 — DAILY ACTIVITY LOGGING (Developer-facing)
- Primary input: Google Form (external link + embedded iframe option on the page)
- Google Form fields to capture:
  - Developer name / email
  - Date
  - Activity type (multi-select): Feature Development, Bug Fix, Code Review, Debugging, Peer Help / Mentoring, Knowledge Sharing, Documentation, Production Incident, Learning / Research, Meetings, Refactoring, Infrastructure Work, Testing
  - Time spent per activity (in hours, 0.5 increments)
  - Stress/Energy level at end of day (1–10 scale)
  - Notes (optional free text)
- After form submission, Google Sheets receives the data automatically
- Flask polls or receives webhook trigger to fetch latest Sheet data
- Data ingested into MongoDB (raw activity_logs) and processed through classification engine

MODULE 3 — WORK CLASSIFICATION ENGINE (Python backend)
- Classify each activity as Visible Work or Invisible Work using predefined mapping:
  VISIBLE: Feature Development, Bug Fix (when ticket-tracked), Testing (formal QA)
  INVISIBLE: Code Review, Debugging (non-ticket), Peer Help, Mentoring, Knowledge Sharing, Documentation, Production Incident response, Learning/Research, Refactoring, Infrastructure, Meetings
- Classification rules stored as a configurable Python dict/JSON — not hardcoded logic
- Classification result stored back into MongoDB alongside original log entry
- Edge cases handled: unrecognized activity types default to "Uncategorized" with a flag

MODULE 4 — CUSTOM METRICS ENGINE (Python backend)
Implement these two custom metrics with full mathematical precision:

METRIC 1 — Invisible Work Ratio (IWR):
  IWR = (Total Invisible Work Hours) / (Total Work Hours) × 100
  - Computed per developer per day, per week, per month
  - Stored in MySQL as metric_snapshots table for trend querying
  - Threshold flags: IWR > 60% = High Invisible Load (flagged yellow), IWR > 75% = Critical (flagged red)

METRIC 2 — Burnout Correlation Score (BCS):
  BCS = weighted composite of:
    - 7-day rolling average of daily hours logged (weight: 0.3)
    - 7-day rolling average of stress/energy level (inverted: 10 - score) (weight: 0.4)
    - IWR trend over 7 days (increasing IWR = higher risk) (weight: 0.3)
  Normalized to 0–100 scale. Score > 70 = burnout risk alert.
  Use scipy.stats.pearsonr to calculate correlation between invisible work hours and stress level over rolling 14-day windows.
  Document: using scipy.stats.pearsonr for Pearson correlation between invisible work load and developer stress index.

Additional computed metrics:
  - Productivity Invisibility Index (PII): ratio of invisible work hours to total visible output units (commits + tickets) per week
  - Daily effort distribution breakdown (visible vs invisible as % per day)
  - Week-over-week IWR change (trend direction)

MODULE 8 — GOOGLE SHEETS DATA PIPELINE (Python backend service)
- sheets_service.py: authenticates via Service Account from env var GOOGLE_SERVICE_ACCOUNT_JSON
- Polls the connected Google Sheet every 5 minutes (configurable interval in .env)
- Reads new rows since last processed timestamp (stored in MongoDB as pipeline_state collection)
- Converts raw Sheet rows to Pandas DataFrame immediately
- Passes DataFrame to data_cleaner.py → classifier.py → metrics_engine.py pipeline
- Writes processed metrics back to MySQL metric_snapshots
- Error handling: exponential backoff on API rate limit (429), skip and log malformed rows, alert on consecutive failures > 3

- Files saved to /reports/ directory using pathlib — cross-platform safe
